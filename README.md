# КП 2.3. TaskFlow

Виконав: курсант групи С-44 Старжинський Сергій.

Варіант 17. Проєкт виконано за прикладом із методички КП 2.3.

## Запуск

1. Розпакувати архів у нову папку `KP2_3_Variant17`.
2. У VS Code вибрати **Файл → Відкрити папку** та відкрити папку, у якій лежить `package.json`.
3. Відкрити термінал. У Windows можна вибрати **Command Prompt (cmd)**.
4. Виконати команди по черзі:

```bat
npm install
npm run dev
```

Відкрити адресу, яку покаже термінал, зазвичай http://localhost:5173.
Для зупинки сервера натиснути **Ctrl+C**.
Для роботи потрібні Node.js та Git. Проєкт перевіряється з Node.js 24.

## Що показує застосунок

Головна сторінка містить чотири завдання, їхні описи, статуси й пріоритети.
Лічильник показує кількість виконаних завдань: спочатку **1 / 4**.
Кнопка **«Про застосунок»** відкриває другу сторінку.
Стрілка **«Назад»** і кнопка **«На головну»** повертають до списку.

Дані змінюються у файлі `src/data/tasks.js`, як у прикладі викладача.
Кнопок додавання, видалення або редагування завдань у прикладі методички немає.

## Перевірка PWA

Після зупинки сервера виконати:

```bat
npm run build
npm run preview
```

Відкрити адресу з термінала, зазвичай http://localhost:4173.

1. Перевірити список завдань і переходи між сторінками.
2. Натиснути **F12 → Application → Manifest**: назва TaskFlow, режим standalone, дві іконки.
3. Відкрити **Application → Service Workers** і перевірити реєстрацію `sw.js`.
4. Після активації Service Worker перезавантажити сторінку, увімкнути **Offline** у DevTools і ще раз перезавантажити її. Список має залишитися доступним. Потім вимкнути Offline.
5. У Chrome або Edge перевірити встановлення застосунку через значок біля адреси або меню браузера.

PWA перевіряється через `npm run preview` або на опублікованому HTTPS-сайті.
У режимі `npm run dev` перевіряються сторінки та компоненти.

Іконки вже додані в `public/icons`. Якщо змінюється `icon.svg`, для повторного створення PNG виконати:

```bat
node scripts/generate-icons.mjs
```

## Новий репозиторій GitHub

1. Увійти в GitHub під акаунтом **Ecstasy26**.
2. Відкрити https://github.com/new.
3. Назвати репозиторій **KP2_3_Variant17**, вибрати **Public**.
4. Створити порожній репозиторій: не додавати README, .gitignore та ліцензію на сайті. Потрібні файли вже є в проєкті.
5. У терміналі папки з `package.json` виконати:

```bat
git init
git branch -M main
git add .
git status
git commit -m "Add TaskFlow for KP 2.3"
git remote add origin https://github.com/Ecstasy26/KP2_3_Variant17.git
git push -u origin main
```

Перед комітом `git status` має показувати код і конфігурацію, а не `node_modules` або `dist`.
Файл `package-lock.json` потрібно залишити в репозиторії.
Якщо відкриється вхід у GitHub, вибрати **Ecstasy26**.

## Cloudflare

Відкрити https://dash.cloudflare.com/ → **Workers & Pages → Create application**.
Вибрати підключення GitHub-репозиторію (**Import a repository / GitHub**), дати доступ до `KP2_3_Variant17` та вибрати його.

| Поле | Значення |
| --- | --- |
| Project / Worker name | `kp2-3-variant17` |
| Production branch | `main` |
| Root directory | `/` |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |
| Preview command | `npx wrangler preview` |

Назва Worker має збігатися зі значенням `name` у `wrangler.jsonc`.
Натиснути **Deploy**, дочекатися успішної збірки та відкрити надане посилання `workers.dev`.
Якщо доступ за `workers.dev` вимкнений, увімкнути його в налаштуваннях доменів Worker.

Папка `dist` створюється на Cloudflare під час збірки. Завантажувати її в GitHub не потрібно.

## Використані технології

- **Vue 3** відображає дані та обчислює кількість виконаних завдань.
- **Framework7** надає сторінки, панель навігації, кнопки та маршрутизацію.
- **Vite** запускає середовище розробки та створює готову збірку.
- **PWA** дає змогу встановити застосунок і відкрити попередньо завантажені сторінки без мережі.
- **GitHub** зберігає код та історію змін.
- **Cloudflare Workers** публікує готовий сайт.

## Основні файли

| Файл або папка | Призначення |
| --- | --- |
| `src/main.js` | Створює Vue-застосунок і підключає Framework7 |
| `src/App.vue` | Містить головний контейнер і налаштування застосунку |
| `src/routes.js` | Визначає маршрути `/` та `/about/` |
| `src/components/TaskCard.vue` | Показує одну картку завдання |
| `src/pages/HomePage.vue` | Виводить список і лічильник виконаних завдань |
| `src/pages/AboutPage.vue` | Показує інформацію про застосунок |
| `src/data/tasks.js` | Зберігає масив із чотирма завданнями |
| `src/css/app.css` | Задає оформлення сторінок і карток |
| `public/icons/` | Містить SVG-іконку та PNG розмірами 192 і 512 пікселів |
| `scripts/generate-icons.mjs` | Створює PNG-іконки з SVG через sharp |
| `vite.config.js` | Налаштовує Vite, Manifest і Service Worker |
| `wrangler.jsonc` | Налаштовує публікацію папки `dist` на Cloudflare |
| `.gitignore` | Виключає залежності, збірку та локальні налаштування з Git |
| `.gitattributes` | Узгоджує закінчення рядків текстових файлів |

`HomePage.vue` імпортує масив із `tasks.js`, перебирає його через `v-for`
та передає кожне завдання компоненту `TaskCard` через властивість `task`.
Компонент отримує цю властивість через `defineProps` і показує статус та пріоритет українською.
